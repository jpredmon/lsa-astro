## Context

Phases 1–4 (scaffold, tokens, header/nav, hero) are complete and live at `lsa-astro.pages.dev`. The migration spec's own section 6.3 undersells this phase as "two text blocks: What we do / Why we do it" — live research shows the actual section is five pieces in sequence: **About us** headline → YouTube video → **What we do** headline + body → **Why we do it** headline + body. Building to the live site's real structure, not the spec's abbreviated summary, per the spec's own stated goal (section 1: "exact visual/behavioral replica").

**Research method:** live HTML via `curl` with a realistic UA, plus live Chrome computed-style/stylesheet inspection against `https://skatelawrence.com` — including resolving Elementor's global-kit CSS custom properties (`--e-global-typography-*`) across all three responsive breakpoints, not just reading the single top-level rule.

## Key discovery 1: AnimatedHeadline reuse needs two small extensions

`AnimatedHeadline` (built in Phase 4 for Hero) is reused here for "About us"/"What we do"/"Why we do it", confirmed live to share the exact same SVG path/viewBox and the same centered/oversized-by-20px underline positioning as Hero (already generic, no change needed — see Phase 4 lessons). Two things Hero's usage never exercised, both confirmed live:

1. **All three headlines are 100% highlighted text, no plain prefix.** Live markup for "About us"/"What we do"/"Why we do it" has a single `<span class="elementor-headline-dynamic-text">` containing the whole string — unlike Hero's "Make Lawrence " + "Skateable" split. The component currently renders `{plainText}{' '}` unconditionally before the highlight, which would inject a stray leading space when `plainText` is empty. Fix: make `plainText` optional (default `''`) and only render it (plus the trailing space) when non-empty.
2. **Different typography, not a scaled version of Hero's.** Live-resolved via `.elementor-kit-5` custom properties across all three `@media` breakpoints:

   | | Hero (existing `hero` variant) | About/What/Why (new `section` variant) |
   |---|---|---|
   | Desktop font-size | 120px | 50px |
   | ≤1024px | 64px | 30px |
   | ≤767px | 45px | 26px |
   | line-height | 0.9em | 1.2em |
   | text-align | left | center |
   | tag | `h3` | `h2` |

   The `section` variant's values (50/30/26px, 1.2em, bold, `#1D1C1C`) are an **exact match for this project's own generic `--font-size-h2`/`--line-height-h2` tokens already defined in `tokens.css`** (Phase 2 captured them correctly) — so the `section` variant doesn't need its own hardcoded font-size at all, unlike Hero. It only needs `text-align: center`; font-size/weight/line-height/color come for free from `base.css`'s existing `h2 { font-size: var(--font-size-h2); ... }` rule once `as="h2"` is set.

   Adds a `variant?: 'hero' | 'section'` prop, default `'hero'` — **zero visual change to Hero**, since its existing hardcoded 120/64/45px + left-align rules move under a `.headline--hero` modifier class that's still applied by default.

## Key discovery 2: cycle duration is already solved

All three instances use `highlight_iteration_delay: 8000` (confirmed live) — exactly the `cycleDurationMs={8000}` variant already built and shipped in the previous fix. No new work here, just pass the prop.

## Key discovery 3: About Us section structure and styling (live-confirmed)

Fetched raw HTML (`#about-us-id` through the element right before `#parks-id`) plus live `getComputedStyle`/stylesheet inspection:

- **"About us" headline** — `<section id="about-us-id">` (nav's existing `#about-us-id` anchor link, built in Phase 3, targets this exact id), boxed/centered at `--container-max-width` (1260px), transparent background (site `<html>` background is `--color-white`, confirmed live).
- **Video** — YouTube embed, `https://youtu.be/idV0zTsyBPM`, confirmed live as a `www.youtube-nocookie.com` iframe (privacy-enhanced mode, matches the source `yt_privacy: yes` setting), `aspect-ratio: 16/9`, container `max-width: min(100%, 1260px)`. **Needs a CSP change**: `frame-src` currently only allows `https://*.paypal.com`; must add `https://www.youtube-nocookie.com`.
- **"What we do" headline** — same treatment as About us, id `what-we-do-id` (no nav anchor targets this one, but keeping the id for parity/future-proofing since the live site has it).
- **"What we do" body** — plain `<h5>Advocate, fundraise for, create and manage safe places to skate/ride in the greater Lawrence area.</h5>`, full-width section (not boxed), background `--color-cream-2`, `padding: 40px` top/bottom (live-confirmed, a value distinct from the existing `--space-*` scale — added as a new token), text centered (confirmed live, live h5 typography is an **exact match for this project's existing generic `--font-size-h5`/`--line-height-h5` tokens** — zero custom CSS needed beyond the section wrapper's background/padding/text-align).
- **"Why we do it" headline** — same pattern, id `why-we-do-it-id`.
- **"Why we do it" body** — plain `<h5>Skateboarding improves mental health, fosters community, and encourages diversity and resilience. This applies to all skatepark users and riders on the streets.</h5>`, same section styling as the first body block.
- **Inter-section vertical spacing**: live gaps between elements (About-headline→video ~90px, video→What-headline ~130px, What-headline→body ~170px, etc.) don't reduce to one clean token — Elementor's flex-centered `min-height` sections don't map to simple padding. Building with reasonable spacing from the existing `--space-*` scale first, then true-up via live side-by-side screenshot diff during QA (Task 6) rather than fully reverse-engineering Elementor's internal box model — consistent with the spec's own iterative per-section QA approach (section 4).

## Recommended approach

**Component structure:**

```
src/components/
  About.astro                    # section wrapper: all 5 pieces in sequence
  about/
    AboutVideo.astro             # YouTube nocookie iframe, 16:9, lazy-loaded
  hero/
    AnimatedHeadline.astro       # MODIFIED: +variant prop, optional plainText
```

**`AboutVideo.astro`** — a plain `<iframe>` (not a JS-hydrated component; Astro ships zero JS by default and this needs none), `loading="lazy"`, `src="https://www.youtube-nocookie.com/embed/idV0zTsyBPM"`, wrapped in a `div` with `aspect-ratio: 16/9` so the iframe can be `width: 100%; height: 100%` without a padding-bottom hack.

**`About.astro`** — five sections in document order, using the extended `AnimatedHeadline` with `variant="section"` and `cycleDurationMs={8000}` for all three headline instances, plain `<h5>` for both body blocks (no wrapper component needed — matches the "don't build a component for something that's just a styled semantic tag" pattern already used for Hero's kicker `<h4>`).

## Execution notes (post-completion)

Executed via superpowers:subagent-driven-development in an isolated worktree (branch `worktree-phase5-about-us`). All 6 tasks passed individual review clean on the first attempt (no fix-loop rounds). The final whole-branch review then caught 4 Important findings invisible at per-task scope:

1. **Section padding still didn't match live** — an earlier live-QA pass (Task 6) had correctly fixed inter-section *margins* (110px) but never compared the sections' own internal *padding*, leaving headline sections ~80px too tall each. Fixed with a second round of direct live-vs-local `getComputedStyle` padding comparison. Lesson generalized into memory: measuring gaps between elements is not the same as measuring the elements themselves.
2. **`pulseDurationMs`'s inline `style=""` attribute was silently dropped by this project's CSP in production** — the same inline-style-attribute restriction already known for `define:vars` turned out to apply to *any* inline `style=""`, including a plain hardcoded string that was never `define:vars`-based. Pre-existing on Hero since Phase 4 (undetected because `astro dev` never serves `_headers`/CSP), this diff would have propagated the same broken pattern onto 3 more elements. Fixed by hardcoding the duration directly into the component's scoped `<style>` block instead.
3. A stale code comment (written when only Hero used this component) was corrected to describe both variants.
4. A Prettier formatting gap on the two new files was fixed.

A discovered-but-explicitly-scoped-out cosmetic residual remains: `.about__video-section`'s pre-existing `padding-bottom` leaves a ~30px gap vs. live between the "About us" and "What we do" headlines — parked as a minor, non-blocking item for a future pass.
