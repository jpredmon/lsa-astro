**Goal:** Build the Our Parks section: "Our parks" headline, then 5 park photos in sequence (Centennial, Corey Lawrence Vert Ramp, Edgewood DIY, Holcom, Deerfield), each with a caption/photo-credit/external link, desktop/mobile responsive image swap.

## Context

## Key discovery 1: the spec's "5-image grid" is wrong — it's a single-column stack

Spec section 6.4 says "Our Parks — 5-image grid." Live-measured: the container is `display: flex; flex-direction: column; gap: 20px` — a **vertical single-column stack** of full-width (1024px, capped at the 1260px container) images, not a multi-column grid, even at desktop (1536px viewport, confirmed). Building to the live behavior (stack), not the spec's word, per the spec's own stated goal (exact replica) — same category of correction as Phase 5's "two text blocks" undersell.

## Key discovery 2: responsive breakpoint differs from HeroPhoto's — do not copy that pattern verbatim

`HeroPhoto.astro`'s `<source media="(max-width: 767px)">` swaps to the small image on **phone only** (tablet uses the large image). Our Parks' live markup uses a **different split**: the large-image container has classes `elementor-hidden-tablet elementor-hidden-mobile` (hidden ≤1024px, i.e. shows desktop-only, ≥1025px) and the small-image container has `elementor-hidden-desktop` (hidden ≥1025px, i.e. shows at both tablet AND phone, ≤1024px). Per `src/styles/breakpoints.ts`, that's `<source media="(max-width: 1024px)">` for `ParkPhoto.astro` — **1024px, not 767px**. Confirmed live: both the large-image and small-image containers use the same `display:flex; gap:20px` stack internally: only one of the two is ever visible at a given viewport (`display:none` on the other), so only one image is ever fetched per viewport — same double-fetch prevention as `HeroPhoto.astro`, different breakpoint.

## Key discovery 3: photo/caption styling is identical to Hero's and About's — direct reuse, no new measurement needed

Live-confirmed on the Centennial instance: caption `text-align: center`, `font-size: 12.8px` (same non-tokenized literal already used in `HeroPhoto.astro`), `color: #1D1C1C` (`--color-ink`), credit link wrapped in `<strong>` colored `--color-highlight-yellow`, `text-decoration: none`. Section background is transparent (site `<html>` background, `--color-white`) — same as Hero/About headline sections.

## Key discovery 5: vertical spacing — partially decomposed, rest trued up during QA

Live-measured gap from the "Our parks" `<h2>`'s bottom to the first image's top: **80px total**, decomposed via precise `getBoundingClientRect()` deltas into three segments — 20px (h2-to-spacer, source unclear: all measured padding/margin on the h2/widget-wrap/section chain read `0px`, so this may be section `min-height` slack rather than a box-model property), 50px (an empty spacer widget, same live pattern as Phase 5's About-to-video spacer), 10px (spacer-to-image). Unlike Phase 5's About Us (where the whole gap resolved cleanly to measurable padding), this one has an unexplained 20px component. Build with the 60px (spacer + trailing gap) folded into `.parks__grid-section`'s `padding-top`, per the established About-Us pattern, and treat the remaining ~20px as an approximation to true up via live side-by-side diff during QA (Task 5) — don't block on fully explaining its source.

The "Our parks" headline section itself reuses the exact same `padding: 10px` top/bottom pattern already confirmed for About Us's headline sections (`--space-about-headline` token) — since this is now confirmed to apply to a **second** independent section using the same underlying Elementor widget type, **rename it to a non-About-specific name** (`--space-headline-section`) and update the one existing consumer (`About.astro`) alongside adding the new one (`Parks.astro`), rather than leaving a stale "about"-scoped name for something now proven site-wide.

## Recommended approach

**Component structure:**

```
src/components/
  Parks.astro                    # section wrapper: headline + 5 ParkPhoto instances
  parks/
    ParkPhoto.astro              # reusable: desktopSrc/mobileSrc/alt props + slot for caption markup
```

**`ParkPhoto.astro`** — same `getImage()` + `<picture><source media="(max-width: 1024px)">` technique as `HeroPhoto.astro` (see Key discovery 2 for why the breakpoint differs), `loading="lazy"` (below the fold, unlike Hero's eager). Caption content varies per instance (link-only, prefix+link+suffix, or plain+link) — rather than modeling every combination as props, the component provides the `<figure>`/`<picture>`/`<figcaption>` structure and styling, and the caller supplies the actual caption markup via a default `<slot />`. This mirrors how `HeroPhoto.astro` hardcodes its own one-off caption inline; with 5 varying captions here, a slot avoids forcing an artificial prefix/suffix prop API onto 3 different real shapes.

**`Parks.astro`** — headline section (`id="parks-id"`, matching Nav's existing `#parks-id` anchor from Phase 3) + a single `.parks__grid-section` containing 5 `<ParkPhoto>` calls in document order, each with its own inline slot content per the table above.

### Task 3: Create `ParkPhoto.astro`

**Files:** Create `src/components/parks/ParkPhoto.astro`

```astro
---
import { getImage } from 'astro:assets';

interface Props {
  desktopSrc: ImageMetadata;
  mobileSrc: ImageMetadata;
  alt: string;
}

const { desktopSrc, mobileSrc, alt } = Astro.props;

const desktop = await getImage({ src: desktopSrc, width: 1024, height: 682, format: 'webp' });
const mobile = await getImage({ src: mobileSrc, width: 480, height: 320, format: 'webp' });
---

<figure class="park-photo">
  <picture>
    <source media="(max-width: 1024px)" srcset={mobile.src} width="480" height="320" />
    <img src={desktop.src} width="1024" height="682" alt={alt} loading="lazy" class="park-photo__image" />
  </picture>
  <figcaption class="park-photo__caption">
    <slot />
  </figcaption>
</figure>

<style>
  .park-photo {
    margin: 0;
  }

  .park-photo__image {
    display: block;
    width: 100%;
    height: auto;
  }

  .park-photo__caption {
    margin: var(--space-xs) 0 0;
    font-size: var(--font-size-caption);
    color: var(--color-ink);
    text-align: center;
  }

  .park-photo__caption :global(a) {
    text-decoration: none;
  }

  .park-photo__caption :global(strong) {
    color: var(--color-highlight-yellow);
  }
</style>
```
