## Context

Phases 1–3 (scaffold, tokens, header/nav) are complete and live at `lsa-astro.pages.dev`. This phase builds kicker text, `AnimatedHeadline`, hero photo with caption, and the sitewide `CursorDot`.

**Research method:** live HTML/CSS via `curl` with a realistic browser UA, plus live Chrome browser automation against `https://skatelawrence.com` — including forcing `AnimatedHeadline`'s entrance trigger via a real scroll event (it starts with no SVG in the DOM at all — injected by the theme's JS only once triggered) to capture the actual markup, extracting `@keyframes` directly from live stylesheets, and polling computed styles across a full animation cycle.

**Two corrections caught during planning** (verified independently, not accepted at face value):

1. An initial draft assumed centered text; live-measured `text-align: start` (left-aligned) — corrected.
2. An initial draft used two eagerly-loaded `<Image>` components toggled by CSS `display:none`. **Real bug, not just inaccuracy**: browsers fetch `<img src>` regardless of computed `display:none`, so both images would download on every device — contradicts the spec's own performance goals. Fixed with `getImage()` + native `<picture>`/`<source media>` so only the matching image is ever fetched.

## Key discovery: AnimatedHeadline's underline SVG doesn't exist until triggered

The widget starts with class `elementor-invisible` and zero `<svg>` in its subtree. Only after a real scroll event does the theme's JS add `animated pulse` classes AND inject the underline `<svg>`. Captured live:

- Entrance ("pulse"): `animation-duration: 1.25s`, `ease`, 1 iteration — standard Animate.css pulse.
- Underline draw: injected `<svg viewBox="0 0 500 150" preserveAspectRatio="none">` with `<path d="M7.7,145.6C109,125,299.9,116.2,401,121.3c42.1,2.2,87.6,11.8,87.3,25.7">` (matches `data-settings` verbatim). `stroke: #EED338`, `stroke-width: 20px`, `fill: none`. Two live-extracted `@keyframes` (draw 1.2s, hide/fade 0.4s), JS-toggled every 5000ms.

**Simplification:** combined into one self-contained CSS `@keyframes` (draw 0–24%, hold 24–92%, fade+blur 92–100% of a 5s infinite cycle) — zero JS needed.

## Recommended approach

**Component structure:**

```
src/components/
  Hero.astro
  hero/
    AnimatedHeadline.astro
    HeroPhoto.astro
  CursorDot.astro
```

**`AnimatedHeadline`** takes `plainText`, `highlightedText`, `as` (default `'h3'`), `pulseDurationMs` (1250), `drawDurationMs` (1200, informational only), `cycleDurationMs` (5000) — designed for reuse by a later phase without redesign. Known limitation documented in the component: keyframe percentages are hardcoded to Hero's 1200:5000 ratio.

**Entrance "pulse":** no JS trigger — Hero is always above the fold, so autoplay-on-paint is visually identical to scroll-into-view for above-the-fold content.

**HeroPhoto:** `getImage()` + `<picture><source media>` — native browser matching means only one image is ever fetched.

**CursorDot:** the only piece needing real JS. Built the live site's actual way (CSS-transition-based `top`/`left`/`width`/`height`, not rAF+lerp).

**TDD for CursorDot's logic:** position math (`computeDotPosition`) and size/opacity mapping (`getDotSize`) extracted into `src/lib/cursor-dot.ts`, tested with Vitest (vetted: v4.1.10, published 2 days ago, actively maintained), written test-first. The Astro component's inline `<script>` stays thin DOM-wiring around the tested functions.

- [x] **Step 1: Create the file**

```astro
---
interface Props {
  plainText: string;
  highlightedText: string;
  as?: 'h2' | 'h3' | 'h4';
  pulseDurationMs?: number;
  drawDurationMs?: number;
  cycleDurationMs?: number;
}

const {
  plainText,
  highlightedText,
  as: Tag = 'h3',
  pulseDurationMs = 1250,
  drawDurationMs = 1200,
  cycleDurationMs = 5000,
} = Astro.props;
---

<Tag class="headline">
  {plainText}{' '}
  <span class="headline__highlight-wrap">
    <span class="headline__highlight">{highlightedText}</span>
    <svg
      class="headline__underline"
      viewBox="0 0 500 150"
      preserveAspectRatio="none"
      aria-hidden="true"
      focusable="false"
      data-draw-duration-ms={drawDurationMs}
    >
      <path d="M7.7,145.6C109,125,299.9,116.2,401,121.3c42.1,2.2,87.6,11.8,87.3,25.7"></path>
    </svg>
  </span>
</Tag>

<style
  define:vars={{ pulseDuration: `${pulseDurationMs}ms`, cycleDuration: `${cycleDurationMs}ms` }}
>
  .headline {
    animation: headline-pulse var(--pulseDuration) ease 1;
  }

  @keyframes headline-pulse {
    from {
      transform: scale3d(1, 1, 1);
    }
    50% {
      transform: scale3d(1.05, 1.05, 1.05);
    }
    to {
      transform: scale3d(1, 1, 1);
    }
  }

  .headline__highlight-wrap {
    position: relative;
    display: inline-block;
  }

  .headline__highlight {
    position: relative;
    z-index: 1;
  }

  /* overflow: visible — the path's y-values (up to ~146) plus half the 20px
     stroke-width exceed the 150-tall viewBox; without this the stroke's
     bottom edge clips. */
  .headline__underline {
    position: absolute;
    inset: 0;
    z-index: 0;
    overflow: visible;
    pointer-events: none;
  }

  .headline__underline path {
    fill: none;
    stroke: var(--color-highlight-yellow);
    stroke-width: 20px;
    animation: headline-underline-loop var(--cycleDuration) ease infinite;
  }

  /* Combines the live site's two separately-JS-toggled keyframes
     (elementor-headline-dash + hide-highlight) into one self-contained loop,
     timed at Hero's live ratio: draw 0-1200ms (0-24%), hold 1200-4600ms
     (24-92%), fade+blur out 4600-5000ms (92-100%), instant reset into the
     next iteration at 0%. */
  @keyframes headline-underline-loop {
    0% {
      stroke-dasharray: 0, 1500;
      opacity: 1;
      filter: blur(0);
    }
    24% {
      stroke-dasharray: 1500, 1500;
      opacity: 1;
      filter: blur(0);
    }
    92% {
      stroke-dasharray: 1500, 1500;
      opacity: 1;
      filter: blur(0);
    }
    100% {
      stroke-dasharray: 1500, 1500;
      opacity: 0;
      filter: blur(10px);
    }
  }
</style>
```

## Task 8: GREEN — implement `cursor-dot.ts`

**Files:**

- Create: `src/lib/cursor-dot.ts`

- [x] **Step 1: Write minimal implementation**

```ts
export interface DotPosition {
  top: number;
  left: number;
}

export interface DotSize {
  width: number;
  height: number;
  opacity: number;
}

const BASE_SIZE = 10;
const HOVER_SIZE = 70;
const BASE_OPACITY = 1;
const HOVER_OPACITY = 0.2;

export function computeDotPosition(
  clientX: number,
  clientY: number,
  width: number,
  height: number
): DotPosition {
  return {
    top: clientY - height / 2,
    left: clientX - width / 2,
  };
}

export function getDotSize(isHovering: boolean): DotSize {
  return isHovering
    ? { width: HOVER_SIZE, height: HOVER_SIZE, opacity: HOVER_OPACITY }
    : { width: BASE_SIZE, height: BASE_SIZE, opacity: BASE_OPACITY };
}
```

## Task 9: Create `CursorDot.astro`

**Files:**

- Create: `src/components/CursorDot.astro`

- [x] **Step 1: Create the file**

```astro
<div id="mouse-dot" class="mouse-dot" aria-hidden="true"></div>

<style>
  .mouse-dot {
    position: fixed;
    top: 0;
    left: 0;
    z-index: 10000;
    width: 10px;
    height: 10px;
    border-radius: 50%;
    background-color: var(--color-highlight-yellow);
    opacity: 1;
    pointer-events: none;
    transition:
      top 0.3s linear,
      left 0.3s linear,
      width 0.3s linear,
      height 0.3s linear,
      opacity 0.3s;
  }

  /* Not independently re-verified against the live site this session —
     carried over from the pre-rebuild legacy component as a reasonable,
     low-risk default for hiding the follower on touch devices. */
  @media (hover: none) {
    .mouse-dot {
      display: none;
    }
  }
</style>

<script>
  import { computeDotPosition, getDotSize } from '../lib/cursor-dot';

  const HOVER_SELECTOR = 'a, button';
  const dot = document.getElementById('mouse-dot');

  if (dot) {
    let width = 10;
    let height = 10;

    function applySize(isHovering: boolean) {
      const size = getDotSize(isHovering);
      width = size.width;
      height = size.height;
      dot.style.width = `${size.width}px`;
      dot.style.height = `${size.height}px`;
      dot.style.opacity = String(size.opacity);
    }

    document.addEventListener('mousemove', (event) => {
      const { top, left } = computeDotPosition(event.clientX, event.clientY, width, height);
      dot.style.top = `${top}px`;
      dot.style.left = `${left}px`;
    });

    document.addEventListener('mouseover', (event) => {
      if (event.target instanceof Element && event.target.closest(HOVER_SELECTOR)) {
        applySize(true);
      }
    });

    document.addEventListener('mouseout', (event) => {
      if (event.target instanceof Element && event.target.closest(HOVER_SELECTOR)) {
        applySize(false);
      }
    });
  }
</script>
```
